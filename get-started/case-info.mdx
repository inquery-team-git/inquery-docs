## Understanding View Modes

Case Info operates in two distinct modes that show data at different levels of aggregation.

<AccordionGroup>
  <Accordion title="Case-Level View (Default)">
    **What it shows:** Aggregated and grouped data across the entire case.

    **How it works**

    - AI groups similar items together intelligently
    - One row per unique medication/diagnosis/procedure
    - Shows all mentions across documents
    - Adds enriched data like timelines and validation

    **When to use**

    - Default for most workflows
    - Building consolidated lists (meds, diagnoses, procedures)
    - Exporting a complete view

    **Example**

    ```
    Lisinopril 10mg
      • First mentioned: 1/15/2024
      • Last prescribed: 3/10/2024
      • 3 mentions across 3 documents
      • Status: Currently prescribed
    ```

    ![Case-Level View](/images/case-level-view.png)
  </Accordion>
  <Accordion title="Section-Level View">
    **What it shows:** Raw extractions from each individual document section.

    **How it works**

    - Each row is a single extraction from one document
    - Duplicates are expected across documents
    - Shows exact quotes as they appear in source documents
    - No grouping or deduplication

    **When to use**

    - Verifying extraction correctness
    - Troubleshooting grouping issues
    - Understanding context

    **Example**

    ```
    Document 1 (1/15/2024): Lisinopril 10mg
    Document 2 (2/20/2024): Lisinopril 10 mg daily
    Document 3 (3/10/2024): Lisinopril 10mg PO daily
    ```

    ![Section-Level View](/images/section-level-view.png)
  </Accordion>
  <Accordion title="Switching between views">
    **Toggle Location:** Top-right of the Case Info interface.

    **How to switch**

    1. Find the **View** dropdown/toggle
    2. Select **Case-level** or **Section-level**
    3. The table refreshes

    **What persists**

    - Selected category (Medications, Procedures, etc.)
    - Filters
    - Color coding and notes

    **What changes**

    - Row count
    - Available columns
    - Grouping structure

    <Tip>
      **Default:** Case-level view is recommended for most users. Switch to Section-level primarily for verification and troubleshooting.
    </Tip>
  </Accordion>
</AccordionGroup>

## Updating, Importing, and Exporting

<AccordionGroup>
  <Accordion title="When to rebuild Case Info">
    **Rebuild is needed when**

    - New files uploaded
    - Sections edited (pages added/removed)
    - Extraction errors identified
    - Grouping is incorrect
    - Case Info was not originally requested

    **What rebuild does**

    - Re-runs extraction on all sections
    - Regenerates case-level groupings
    - Updates timelines and validation
    - Preserves user edits (colors, notes)
  </Accordion>
  <Accordion title="How to rebuild Case Info (Admin)">
    <Steps>
      <Step title="Open update modal">
        Click the settings/gear icon or choose **Update Case Info**.
      </Step>
      <Step title="Select categories">
        Choose which categories to rebuild.
      </Step>
      <Step title="Confirm and monitor">
        Processing runs in background with WebSocket progress updates.
      </Step>
      <Step title="Refresh to view results">
        Refresh Case Info after completion.
      </Step>
    </Steps>
    ![Update Case Info Modal](/images/update-case-info-modal.png)
  </Accordion>
  <Accordion title="Selective refresh vs full rebuild">
    **Refresh (faster)**

    - Re-runs enrichment only (timelines/validation)
    - Does not re-extract from documents
    - Available for: Medications, Patient Info, Social History

    **Full rebuild (slower)**

    - Re-extracts from all sections
    - Regenerates groupings and enrichment
    - Use when source data changed or extraction is wrong
  </Accordion>
  <Accordion title="Importing data">
    **Supported categories**

    - Medications
    - Procedures
    - Drug Screens
    - Recommendations
    - Assistive Devices

    <Steps>
      <Step title="Prepare file">
        Create **.xlsx** or **.csv** with required columns for the category.
      </Step>
      <Step title="Upload and map columns">
        Use the import modal to map spreadsheet columns to InQuery fields.
      </Step>
      <Step title="Preview and import">
        Preview rows, then click **Import**.
      </Step>
    </Steps>
    ![Import Mapping](/images/import-mapping.png)

    <Info>
      Imported items are marked with an **Imported** badge so you can distinguish them from AI-extracted data.
    </Info>
  </Accordion>
  <Accordion title="Exporting Case Info">
    **Export options**

    1. Download current view (includes filters)
    2. Download all data (entire category)
    3. Include in case reports (PDF downloads)

    **Formats**

    - Excel (.xlsx)
    - CSV
    - PDF (within case report)

    **Included**

    - Group data + mention details
    - Dates and references
    - Color coding
    - Notes
    - Metadata
  </Accordion>
</AccordionGroup>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Case Info not showing / empty">
    **Possible causes**

    - Service not requested during upload
    - Processing still in progress
    - Extraction failed

    **Solutions**

    1. Confirm Case Info was selected during upload
    2. Request via **Request Additional Services** if not
    3. Wait for processing (check notifications)
    4. Contact support if processing failed
  </Accordion>
  <Accordion title="Missing medications/procedures I know exist">
    **Possible causes**

    - Poor OCR quality (scanned documents)
